Data doesn't disappear between systems

The converter uses a universal intermediate data model.

Activity Codes

Activity codes and their values are extracted into a universal code dictionary. Code names, IDs, descriptions and values are retained even where the destination system uses a different coding structure.

Custom Fields

Text, number, date, duration, flag, cost and other user-defined fields are retained. Destination-native fields are used where possible; otherwise the original field/value pair is preserved as custom data.

Relationships

FS, SS, FF and SF relationships, lag values, relationship IDs and predecessor/successor information are preserved through the universal relationship model.

Calendars

Calendar names, working periods, exceptions, holidays and calendar assignments are retained rather than assuming every project uses a seven-day calendar.

Resources

Resource IDs, names, types, codes, rates, calendars, units, availability and activity assignments are mapped independently from activity conversion.

Audit Trail

Each conversion can retain the original source field, universal field and destination field, allowing users to see exactly where project information went.

Important: MPP, XER and Powerproject are substantially different project formats. The browser interface cannot safely implement a complete proprietary-format conversion engine by itself. The production version should send the file to a conversion backend. The backend should first transform the project into a Universal Project Model and only then generate the destination format. If a field has no native destination equivalent, the converter should preserve the original field name, value and source system rather than silently dropping it.
